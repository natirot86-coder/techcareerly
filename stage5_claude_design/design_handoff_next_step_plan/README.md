# Handoff: תוכנית המשך — ארבעת המסכים

## Overview
אפליקציית ליווי לצעירים אחרי צבא/שירות, בשלב שבו כבר נבחר מסלול לימודים וצריך להוציא אותו לפועל: מגורים, מימון, הרשמה ומלגות. המערכת מחליפה קיר משימות בארבעה מסכים, כשבכל רגע נתון מוצגת פעולה אחת דחופה.

ארבעת המסכים:
1. **מסך פתיחה לשלב** — מסביר מה קורה בשלב הזה (2a)
2. **התוכנית שלי** — כרטיס פעולה דחופה + תוכנית לפי חודשים (2b)
3. **ארון המסמכים** — מצב ריק, מצב הגשה שנייה, והוספת מסמך (3a / 3b / 3c)
4. **סיכום לרכזת** — עדכון שנבנה מעצמו + מסך "לא התקבלתי" (4a / 4b)

הכל בעברית, RTL.

## About the Design Files
הקבצים בחבילה הזו הם **קובצי ייחוס עיצוביים שנכתבו ב-HTML** — פרוטוטייפים שמראים מראה והתנהגות מיועדים, לא קוד production להעתקה ישירה. המשימה היא **לשחזר את העיצובים האלה בסביבת הפיתוח הקיימת של הפרויקט** (React, React Native, Vue, SwiftUI, native וכו') לפי הדפוסים והספריות שכבר מקובלים בו. אם עדיין אין סביבה — לבחור את המסגרת המתאימה ולממש שם.

כל מסך בקובצי הייחוס מצויר כמלבן ברוחב 390px בתוך קנבס סקירה. **הקנבס עצמו, תגיות הזיהוי (2a/3b/…), כרטיסי ההסבר והכותרות של הסבבים אינם חלק מהמוצר** — הם עזרי סקירה בלבד. יש לממש רק את תוכן המלבנים.

## Fidelity
**High-fidelity.** צבעים, טיפוגרפיה, מרווחים, רדיוסים ומלל סופיים ומדויקים. יש לשחזר פיקסל-פרפקט, תוך שימוש בספריות ובקומפוננטות הקיימות בקודבייס.

יוצא מן הכלל: אין אייקונים בעיצוב. במקומות שבהם מופיע עיגול צבעוני (סטטוס) או ריבוע ריק (צ'קבוקס) — יש להחליף באייקון מתוך ספריית האייקונים של הקודבייס. אין תמונות בעיצוב הנוכחי.

## State Management

**Task**: `{ id, title, note, domain, dueDate | null, month, status: 'open' | 'done', source: 'generated' | 'user' }`
**Document**: `{ id, name, status: 'have' | 'missing', fileRef | null, physicalLocations: string[], leadTimeNote | null }`
**Application**: `{ id, name, type: 'scholarship' | 'institution' | 'housing', deadline, requiredDocIds: string[], status: 'draft' | 'submitted' | 'accepted' | 'rejected' | 'waiting' }`
**CoordinatorUpdate**: `{ lastSentAt, includedEvents: Event[], excludedEventIds: string[] }`
**Onboarding**: `{ stagePlanIntroSeen: boolean }`

נגזרות (לא נשמרות): הפעולה הדחופה = המשימה הפתוחה עם ה-dueDate הקרוב; קיבוץ החודשים; ספירת "יש לך N מתוך M" = חיתוך `requiredDocIds` עם מסמכים בסטטוס `have`; תוכן העדכון לרכזת = שינויי סטטוס מאז `lastSentAt`.

**Data fetching:** אחסון קבצים בענן הפרטי של המשתמש (העלאה ישירה מהמכשיר לחשבון האחסון שלו). המערכת שומרת רק הפניה (`fileRef`) וסטטוס. שאר הנתונים מקומיים למכשיר עם סנכרון אם קיים חשבון.
